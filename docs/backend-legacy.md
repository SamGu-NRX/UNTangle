# What to keep from the legacy backend

UNTangle used to run an Express and SQLite API as a git submodule. It lived in Sangharsha Dhakal's [UNT-Schedule-Optimizer](https://github.com/sunnyD1000/UNT-Schedule-Optimizer) repository, with later commits from Sam Gu and vishyj, and the submodule pinned commit `0a49d4d`. This note is for whoever designs our own server. It lists what is worth carrying over and what to leave behind. Paths below are relative to that repository at that commit (`git show 0a49d4d:<path>` after fetching it).

## Worth keeping

- **Count every grade label, not only A to F.** `grade_sections` has a column per bucket (A to F, P, NP, W, WF, I, PR, NPR, Z, and `***` for suppressed counts), puts unknown labels in `other_grades_json`, and sets `total_enroll` to the sum of all of them (`src/db/database.ts:82-106`, `src/db/seed.ts:294-365`). GPA uses only A to F and is null when there are none (`src/lib/grade-metrics.ts:42-60`). `lib/grades-history` already does the same with `counts` and `total`; keep that rule.
- **An idempotent import key.** Each grade row upserts on `source_key = term|subject|number|section|instructor|title` (`src/db/seed.ts:360`), so a re-import updates rows instead of duplicating them.
- **Separate cache lifetimes for hits and misses.** RateMyProfessors results are cached for 14 days, and a confirmed "no match" for 3 days, in their own columns (`src/lib/rmp-cache.ts:5-6`, `:71-78`). That stops repeated lookups for instructors who have no profile.
- **The response shape for a course.** `GET /api/grades/courses/:subject/:number` returns `course`, an `aggregate` with grades and GPA, `terms` newest first, per-instructor summaries with `sectionCount`, `totalEnroll` and `gpa`, and the `sections` (`src/routes/grades.ts:309-348`). The course panel's `CourseGradeView` (`frontend/src/lib/course-history.ts`) keeps the overall and per-instructor parts. The instructor endpoint adds `courseGroups`, one aggregate per course (`:350-413`).
- **A health check that names the service.** `/api/health` returns `service: "untangle-backend"` (`src/server.ts:30-32`), so the dev script could tell our server from some other process on the port.

## Data sources

- **Grades.** `data/grade-distributions/complete.json` is a copy of [jeffw16/unt-grade-distributions](https://github.com/jeffw16/unt-grade-distributions) (MIT, per `data/grade-distributions/SOURCE.md`). It has 22,176 rows over four terms, 2017 Fall to 2019 Spring. The 6,702 "2019 Spring" rows are identical to the "2018 Fall" rows, field for field, so every aggregate over both terms counts that semester twice. The backend imported the file as it was. untgrades.app, which the frontend uses now, replaces it.
- **Sections.** `data/compD.csv` holds 2,704 meeting rows with no term. The seed script gave every row `term = 2025FA`, `max_seats = 30` and `open_seats = 15`, and gave every course 3 credits (`src/db/seed.ts:226`, `:283-287`). None of those values came from UNT. The frontend's bundled sections derive from this file and are labeled synthetic (`frontend/src/lib/data-provenance.ts`).
- **RateMyProfessors.** `src/lib/rmp.ts` posts to RMP's private GraphQL endpoint with a hard-coded `Authorization: Basic dGVzdDp0ZXN0` (`test:test`) header and UNT's school id (`:9-10`, `:129-153`). RMP has no public API, and its terms of use restrict automated access. This note does not check their current wording. We have decided that our server does not fetch, store or show RMP data. At most the app links to RMP's search page, and only after someone has read RMP's terms.

## Don't repeat

- **Instructor ids that change.** Every seed starts with `DELETE FROM` on courses, instructors and grade rows (`src/db/seed.ts:373`), so autoincrement ids are reassigned and any saved `/instructors/:id` link points at someone else. This is why the frontend now sends every `/instructors/:id` link to Courses. Key instructors by a stable identity, such as the first and last name pair that `lib/grades-history` uses.
- **One record per normalized name.** `instructors.normalized_name` is `UNIQUE` (`src/db/database.ts:50`), so two people with the same name share one row. `cleanNameToken` drops every character outside `a-zA-Z`, so a name like "José" becomes "jos" (`src/lib/names.ts:112-118`).
- **Loose RMP matching.** First names match on a shared prefix and last names on a substring (`src/lib/names.ts:129-150`), and if that fails `bestMatch` accepts the first UNT result whose last name matches, whatever the first name is (`src/lib/rmp.ts:176-186`). An instructor named "Li" can get the ratings of someone named "Lin". When matching is uncertain, show nothing.
- **Upstream calls inside the request.** The course endpoint waits on one RMP lookup per uncached instructor, one at a time, before it responds (`src/routes/grades.ts:323`, `src/lib/rmp-cache.ts:141-150`). Refresh in the background and serve what is cached.
- **Auth defaults that are fine only locally.** The JWT secret falls back to `untangle_dev_secret` even in production (`src/config.ts:18`). The token cookie is never `secure`, `POST /api/auth/guest` creates a user row on every unauthenticated call with no rate limit, and the CAS callback returns the raw error message to the client (`src/routes/auth.ts:17-21`, `:34-62`, `:142-146`). The frontend now handles accounts with better-auth, so none of this auth code is needed.
- **Schema changes at startup.** `database.ts` adds columns with `ALTER TABLE` and runs an `UPDATE` that clears old RMP values every time it starts (`:115-139`). Use versioned migrations; the frontend already has Drizzle.
- **Schedules saved as id arrays.** `saved_schedules.sections` is a JSON array of local section ids, and the API never checks that they exist or are numbers (`src/routes/schedules.ts:36-62`). Those ids also change on every re-seed.
