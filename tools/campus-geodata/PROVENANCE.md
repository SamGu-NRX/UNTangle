# Campus contract and source decisions

Both committed graphs implement [campus-map-v0 at ut-campus-map alpha 937b668](https://github.com/SamGu-NRX/ut-campus-map/blob/937b668cedfe610f158d248f9ae01e2bd8b387ad/docs/contracts/campus-map-v0.md). `frontend/src/lib/campus/contract/{model,parse,validate,errors,check,canonical}.ts` and the malformed rejection fixtures were ported from that repository's `packages/map-data/` at this exact revision. Relative import suffixes were adapted for Next.js. Sam authorized this port from his repository. This note identifies the code source; it does not assert a permissive license that the source repository does not declare.

The dataset uses WGS84 longitude then latitude, GeoJSON features, explicit directed edges, resolvable references, and null physical measurements. The upstream parser permits a null source retrieval timestamp when unavailable. The old cached UNT inputs and the first UT fetch receipt lack a completed retrieval timestamp, so those source values remain null. `observed_at` records the response's OSM base timestamp when present; it is not a field-survey date. Future kit fetches record both retrieval time and OSM base time separately.

`contract-build.ts` adapts the existing UNT importer rather than changing its node joins. Node IDs hash rounded coordinate positions; edge IDs hash OSM way ID and directed endpoint IDs. The validator rejects collisions. IDs do not depend on the array index or dataset revision. GeoJSON way features retain each continuous fragment, so clipping cannot fabricate an edge across missing coordinates. Reciprocal pedestrian travel has a separate reversed edge. The importer excludes `foot=no` and private access without an explicit pedestrian override. It preserves UNT's treatment of pedestrian travel as reciprocal; it does not interpret vehicle one-way tags as pedestrian restrictions.

The runtime consumes directed edges without inventing reverse travel. The kit preserves array order, coordinate rounding, first-edge deduplication, distance-first A*, and the 1.4 m/s path and 0.6 m/s stair assumptions. A shortest-distance path is not necessarily the fastest path. Those speeds are model assumptions, not campus measurements. The UNT matrix SHA-256 remains `76e57546e166aa68b6a7d27d7932b67dea8ce9b063e7cb22d28b39e5573ad08b`, identical to alpha 73800b0, including metadata. The regression test checks all 841 matrix pairs against the migrated router and `getWalkingSeconds`.

The UT definition selects 32 academic and student-service building outlines by OSM ID from the named outlines in the wider extract. Names and centroid pins come entirely from OSM. There are no invented building names or hand-positioned pins. The catalogue is a selected subset, not an exhaustive UT directory. Relations are not imported as building outlines. UT anchors search the largest connected component; UNT retains its historical all-node anchor search to preserve the matrix. Both use the same entrance preference and 250 m snap cap. Connectors are geometric estimates and do not establish that a building entrance is physically reachable.

The UT response came from the Overpass Kumi mirror after the main endpoint returned HTTP 504. Its OSM base timestamp is `2026-05-06T03:25:00Z`. The committed verification artifact records the successful query and raw SHA-256. The snapshot is old and requires a later source refresh before any claim about current campus conditions.

Width, slope, cross-slope, step height, and surface are null on every emitted edge. This importer does not parse those physical tags. Access remains `unknown` after the pedestrian filter. Walking routes permit these unknowns as the existing UNT walking model does; they are not step-free or wheelchair routes. The upstream step-free solver and profiles were not ported. A conservative profile that excludes unknown physical measurements cannot establish a route from this data. The UT oracle test compares distance-first A* with an independent directed Dijkstra implementation over the same graph, not with measured real-world travel.

The wider UT extract contains named building features beyond the selected catalogue. `verification.json` distinguishes graph nodes, directed edges, catalogue buildings, and named GeoJSON features. Byte counts cover every committed UT artifact. The kit fails when its catalogue contains an unroutable pair.
